How AI was used in this project

Almost all of Firox Linux was written by an AI. One person, the project's maintainer, decides what gets built, tries it on real computers and accepts or rejects every change. The AI writes the code.

In short: nearly every line of code, the website, the built-in help, the themes, icons and wallpapers, and the screenshots were produced by Claude, an AI model made by Anthropic, working through Claude Code. A human chose the features, reported what was wrong and reviewed and merged each change. If that matters to you, and it reasonably might, you should know it before you install Firox.

Who did what

The maintainer (a person)

  • Started the project and decides what Firox should be.
  • Asks for each feature, in plain words: "a realistic fish tank screensaver", "Active Directory support in firox-policy".
  • Installs the builds on their own computers and reports what doesn't work. For example, the Steam mouse problem was found and confirmed fixed on real hardware.
  • Overrules the AI when it's wrong. For example, they had a change to the Proton Wayland setting reverted.
  • Passes on findings from security scanners. Claude then fixed them, such as certificate checking in the Android app, a file path check, and replacing SHA-1.
  • Reviews and merges, or declines, every pull request.

Claude (an AI model)

  • Writes the code: the desktop programs (Python and GTK), the shell scripts, the image build, the Android app for Firox Stream.
  • Draws the artwork as code: the themes, the SVG icons, the user pictures and the wallpapers. No image-generating AI was used for these.
  • Writes this website, the README and the help that comes with Firox, including this page.
  • Tests its own changes in throwaway Linux containers and takes the screenshots there.
  • Writes the commit messages and pull requests.

How a change is made

  1. The maintainer describes what they want, or what's broken, in a Claude Code session.
  2. Claude reads the existing code, writes the change and tests it in a container. It uses stand-ins for anything a container doesn't have, such as hardware, a game controller, an Active Directory server or an NFS server.
  3. Claude commits the change under the author name Claude, with a link to the session it came from, and opens or updates a pull request.
  4. The maintainer reads it, tries it, asks for fixes, and merges it or not.

AI-made content from other projects

The six saltwater fish in the Fish Tank screensaver (clownfish, blue tang, yellow tang, blue damselfish, royal gramma and pufferfish) come from Reef Glass by Tim Saucer, under CC0. That project made them with AI too: each fish's picture was generated with Z-Image-Turbo and turned into a 3D model with TripoSR. The freshwater fish in the same screensaver are drawn by Firox's own code.

Firox also includes, as is, a great deal of software written by people: Fedora, Universal Blue, Firefox, labwc, Waydroid and the rest. This page is only about the parts made for Firox.

What this means for you

  • AI makes mistakes, including security mistakes. Several have already been found and fixed. Assume there are more. Firox hasn't had an independent security audit.
  • Much of it has only been tested in containers. Features that need particular hardware or servers may never have run on them before release. Examples are joining an Active Directory domain, NFS home folders, some game controllers and some graphics cards. The pull requests say what was and wasn't tested.
  • Be careful in sensitive places. Before using Firox where a security or reliability failure would be costly (a business, a school, anything holding other people's data), read the parts you rely on, or have someone do it.
  • Copyright and licensing. The law on who owns AI-written code is still unsettled in some places. If that matters for how you use Firox, take advice.
  • Problems are welcome. If something is wrong, report it. It will most likely be fixed the same way: the maintainer asks Claude to fix it, then checks the result.

Checking it yourself

None of this is hidden in the project's history:

  • Commits written by the AI have the author Claude, and end with a Co-Authored-By: Claude line and a Claude-Session: link.
  • Pull requests written by the AI end with "Generated with Claude Code".
  • To count them yourself, in a copy of the repository:
git log --no-merges --format='%an' | sort | uniq -c
