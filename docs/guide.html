ujust commands

Type these in the Command Prompt. Run ujust on its own to list everything.

Customising

Adding screen savers

Any program that runs in a terminal can be a screen saver. Create ~/.local/share/firox/screensavers/NAME.conf (or put it in /etc/firox/screensavers/ for every user):

NAME=Pipes
COMMAND=pipes.sh

It shows up in Settings → Screen Saver straight away.

  • How it runs: full screen in a black terminal; it stops when you move the mouse or press a key. For a program that opens its own window instead, add TERMINAL=false.
  • COMMAND can be a script you drop in ~/.local/bin (handy for single-file savers like pipes.sh) or any program on your PATH.
  • Defaults: the built-in savers are in /usr/share/firox/screensavers/, and the default for new users is in /etc/firox/screensaver (none).

Looks, the taskbar and the Start menu

  • Looks: each look's styles are in /usr/share/firox/themes/{classic,modern,glass}/: taskbar, Start menu, pop-ups, notifications, clipboard picker and lock screen. Window frames are in /usr/share/themes/Firox-{Luna,Modern,Glass}.
  • Your own look: copy one of those folders and edit it; it appears in Settings → Appearance automatically. GLASS=1 in its theme.conf gives it the frosted-wallpaper taskbar.
  • Taskbar: your own CSS rules go in ~/.config/firox/panel.css.
  • System defaults: in /etc/xdg/{labwc,waybar,mako,foot,fuzzel}. Anything you put in the matching ~/.config/ folder overrides them; ujust customize-desktop copies them there for you.
  • The Start menu: pinned and default apps are at the top of system_files/usr/bin/firox-startmenu (PINNED, DEFAULT_MFU). It also takes --all-programs, --power and --log-off, which you can bind to keys in labwc's rc.xml.

Building and signing

  • What's built: ghcr.io/<owner>/firox and ghcr.io/<owner>/firox-nvidia-open, built and published nightly by scripts/nightly-build.sh on a home lab build box (below).
  • GitHub Actions: doesn't run on its own: not on pushes, pull requests or a schedule. If the build box is out of action, start Actions → Build container image → Run workflow by hand. Disk images (build-disk.yml) are manual too.
  • Signing: generate a key pair with cosign generate-key-pair and add the private key as the SIGNING_SECRET repository secret. Without it, images still build and signing is skipped.

Building nightly on your own machine

scripts/nightly-build.sh does what the GitHub build does, on a build box in your home lab, using the same Justfile recipes. It:

  • updates its own checkout of main
  • builds the standard and NVIDIA images, then rechunks and tags them
  • pushes to ghcr.io and/or a registry on your network, and signs
  • can also build installer ISOs
  • Needs: git, just, podman, jq and python3 (plus cosign to sign), and about 50 GB of disk. ISOs need root: run the script as root, or give its user passwordless sudo.
  • Settings: copy the example config, then edit it:
cp scripts/nightly-build.conf.example ~/.config/firox-build.conf

To push to ghcr.io, put a token with write:packages in ~/.config/firox-ghcr-token (chmod 600). To update your Firox machines over the LAN, set LOCAL_REGISTRY and switch them to it with sudo bootc switch 192.168.1.10:5000/firox:latest.

Nightly with cron (crontab -e):

MAILTO=you@example.com
30 2 * * *  $HOME/firox/scripts/nightly-build.sh
  • Results: each run writes a log to ~/.local/state/firox-build/ (kept 14 days) and prints a short summary. It exits non-zero if anything failed, so cron mails you.
  • Overlaps: a night that finds the previous build still running skips itself.
  • Options: --variant main|nvidia, --no-push, --dry-run.
  • Testing a pull request: --pr 42 (or --branch NAME) builds it without publishing anything or making ISOs, so you can check it builds before merging.

Known limitations

  • Waydroid: needs a supported GPU for hardware acceleration. Intel and AMD are fine; on NVIDIA it uses software rendering. It doesn't work where Secure Boot blocks its binder module.
  • NVIDIA image: only supports GTX 16 / RTX 20 series and newer cards, because it uses NVIDIA's open driver.
  • PWAsForFirefox: the extension is installed by a Firefox policy on first launch, so Firefox needs network access the first time.
  • New code: much of the desktop (the taskbar, Start menu, Settings and tools) is new and hasn't had much testing on real hardware yet. Report problems on GitHub.
